# Архитектурная приёмка

Дата: 2026-11-08. Область проверки — только `JustOrganizeYourself`.

## Результат

Реализация соответствует выбранному разделению Flutter/Dart + SQLite и отдельно запускаемые вычисления на Python. Основные GTD-сценарии не требуют Python или внешнего сервера. Общие форматы записей, импорта и peer-обмена согласованы между владельцами компонентов в [CONTRACTS.md](CONTRACTS.md).

| Компонент | Проверенная граница |
| --- | --- |
| `apps/joy` | Интерфейс и пользовательские решения; доменные данные проходят через репозиторий. Экраны обмена, разбора, редакторов и графа разделены по функциональным файлам. |
| `packages/joy_core` | Dart без зависимости от Flutter: модель, SQLite, XLSX, исходящий ICS и revision-aware peer-обмен. Отдельный CLI-приёмник запускается независимо от UI. |
| `services/embeddings` | Самостоятельный Python HTTP-сервис с явной установкой модели. Не владеет базой приложения; возвращает векторы и граф по документированному контракту. |
| Платформенные проекты | Android настроен для локального сетевого обмена; macOS entitlements разрешают сеть и выбранные пользователем файлы. Наличие конфигурации не выдаётся за проверку всех ОС. |

Служебные локальные операции не превращены в обязательные сетевые сервисы: иначе автономный телефон зависел бы от отдельного процесса. При этом вычислительный сервис и peer-приёмник имеют собственные команды запуска и независимые проверки.

## Существенные решения и исправления

- UUID — идентичность записи; порядковый номер вычисляется отдельно по UTC-времени и ID. Синхронизация не склеивает независимые задачи по совпавшему номеру.
- Ревизии и ancestry отличают старую копию от конфликта. Разрешение конфликта включает обе истории; stale-state guards защищают применение после предварительного просмотра.
- Replace-импорт является намеренным изменением, а не физическим исчезновением строк: сохраняются минимальные tombstones, осознанное восстановление старой версии получает новую историю. Независимые проверки подтвердили отсутствие воскрешения от старого peer и сохранение неизвестных правок как конфликтов.
- Undo восстанавливает весь предыдущий снимок, включая структуру и настройки. Валидация выполняется до изменения базы.
- Окончательная очистка Trash удаляет текст и дополнительные данные, включая векторы, оставляя историю, необходимую для обмена и нумерации.
- Удалённые назначения разбора не получают новые записи незаметно: управление показывает необходимость перенастройки, а небезопасное действие не меняет Inbox.
- XLSX Replace показывает файл, область и количество записей до применения. ICS сохраняется в UTF-8; календарный сценарий остаётся только исходящим.
- Граф не смешивает несовместимые модели и устаревший исходный текст. Отсутствие модели не блокирует работу приложения. Реальный локальный сервис и путь Flutter → Python → SQLite → XLSX проверены отдельно от синтетических ответов.

Архитектор и критик обменивались замечаниями с исполнителями; найденные расхождения полей и сигнатур согласованы с вызывающими компонентами. Code Humanizer применён с сохранением необходимых проверок, тестов и нормальных соглашений Flutter/Dart/Python. Персонального образца исходного кода не было; искусственная непоследовательность в проект не добавлялась.

## Границы приёмки

Числа, команды и конкретные результаты тестов приведены в [QA_REPORT.md](QA_REPORT.md). В нативном Linux-клиенте подтверждены первый экран, читаемые шрифты, создание записи и её сохранение после перезапуска. Android debug APK собран, но физический Android, домашний Wi-Fi и телефонная точка доступа остаются отдельными непроведёнными проверками. Фактическая загрузка ICS в Google Calendar, Windows и macOS runtime также не объявляются проверенными.

Текущий peer-транспорт — ручной адрес и код по HTTP в доверенной локальной сети. mDNS, QR и TLS не реализованы. Если удаление родителя оставляет независимых живых потомков, небезопасный выбор блокируется с объяснением; молчаливого каскадного удаления или переноса нет. Undo действует в текущем процессе до следующего изменения данных. Эти ограничения описаны, а не скрыты за успешными unit-тестами.

Несогласованные продуктовые возможности не добавлены. Технические дополнения — ID, номера, история изменений, безопасный импорт, обработка недоступных назначений и защита форм — обслуживают уже запрошенные сценарии. Для реализации текущего автономного ядра новых решений владельца не требуется; внешняя приёмка требует соответствующих устройств и сервисов.
