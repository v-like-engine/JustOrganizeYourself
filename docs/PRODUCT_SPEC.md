## Как пользоваться документом

- Требования сгруппированы по стабильным идентификаторам `JOY-…`; новые требования добавляются без перенумерации существующих.
- Незакрытый пункт `[ ]` означает работу, которую ещё предстоит выполнить. Наличие описания в ТЗ не означает, что функция реализована.
- Закрывать пункт `[x]` после реализации и проверки; рядом указывать ссылку на изменение и результат проверки. Если автоматическая проверка не подходит, записывать сценарий и результат ручной проверки.
- Отделять подтверждённые пожелания от предложений по реализации. Не выбирать стек, облачный сервис, формат базы или модель только потому, что они упомянуты как возможный вариант.
- При продолжении разговора дополнять требования и вопросы; не считать текущий список папок и сценариев полным.

## 1. Цель и границы продукта

Приложение для ведения GTD (Getting Things Done): быстро записывать входящие мысли и задачи, разбирать Inbox по одной карточке, вести проекты и пользовательские категории, хранить знания и контакты. Данные сохраняются между сессиями. Обязательна прямая синхронизация устройств по локальной Wi-Fi-сети без внешнего сервера; альтернативный перенос и восстановление всей системы — одним `.xlsx` без потери поддерживаемой информации.

Выбран стек Flutter + Dart для Android и компьютерного приложения, SQLite для локального рабочего хранилища и XLSX для экспорта/восстановления. Android — приоритетная мобильная платформа, iOS пока вне реализации. Python используется для отдельно запускаемых вычислительных сервисов на компьютере; телефон выполняет основные GTD-функции и локальную синхронизацию без Python-сервера. Протокол синхронизации и контракты описаны в `docs/ARCHITECTURE.md` и `docs/CONTRACTS.md`.

Подтверждённые категории:

| Категория | Содержимое | Особенности |
| --- | --- | --- |
| Inbox | Входящие записи | Быстрое добавление; название, необязательное описание, время создания. |
| Projects | Проекты и связанные действия | План, описание, критерий завершения, минимум одно действие; возможны черновики после мобильного разбора. |
| Knowledge | Знания и справочная информация | Название, описание, время создания; узлы общего графа. |
| Contacts | Контакты | Название, описание, время создания; второй тип узлов общего графа. |
| Shopping Lists | Покупки | Предустановленная редактируемая папка; пользовательские подразделы для магазинов, аптек, маркетплейсов и других мест покупки. |
| Calendar | Запланированные события | Дата и время; только экспорт в Google Calendar. Обратный импорт требует отдельного согласования. |
| Delegated | Делегированные задачи | Поле «кому» и дата; точный смысл даты уточняется. |
| Someday / Later | Когда-нибудь / потом | Предложенный стартовый раздел для отложенного. |
| Urgent / By Date / Conditional | Срочное / к дате / по условию | Стартовые варианты организации; состав и поля ещё уточняются. |
| Trash | Отброшенные записи | Обязательная доступная папка; автоматическое удаление после настраиваемого числа дней. |

Стартовый набор помогает начать GTD, но не ограничивает пользователя: можно создавать, переименовывать, описывать, сортировать и удалять папки и подпапки. Trash обязателен; поведение других системных входов при удалении стартовых папок надо уточнить. Восемь направлений свайпа не ограничивают количество папок: нужны вложенные меню.

## 2. JOY-INBOX — главная страница и захват входящих

Главная страница — Inbox. Визуальный ориентир для ввода: большое аккуратное текстовое поле по центру, как центральный composer в веб-интерфейсе ChatGPT; это ориентир компоновки, а не требование копировать продукт. Над полем короткий призыв, например **“Push to Inbox”**.

- [x] **INBOX-01:** сделать Inbox стартовым экраном с большим полем ввода и комментарием над ним.
- [x] **INBOX-02:** добавить отправку через Enter и кнопку со стрелкой; после отправки запись появляется в списке Inbox и сохраняется.
- [x] **INBOX-03:** поддержать название, необязательное описание и время создания. Для быстрого ввода достаточно одного названия.
- [x] **INBOX-04:** под composer показывать существующие записи; в достаточно высоком окне в начальном положении видны примерно две карточки. Не фиксировать их количество на маленьких экранах.
- [x] **INBOX-05:** позволить прокручивать список колесом мыши, тачпадом и касанием.
- [x] **INBOX-06:** при прокрутке сохранять доступ к composer: он может компактно сместиться к верхней части окна, оставаясь читаемым и с аккуратным отступом от края.
- [x] **INBOX-07:** не допускать перекрытия карточек, элементов управления и текста закреплённым composer.
- [x] **INBOX-08:** восстанавливать неразобранный Inbox после закрытия и нового открытия приложения.
- [x] **INBOX-09:** встроить подсказки похожих существующих задач во время набора (`JOY-SUGGEST`), не перекрывая composer.

Экран ввода со списком и режим разбора колоды — разные режимы: требование показывать одну карточку относится к разбору, а не отменяет просмотр Inbox прокруткой.

**Приёмка:** добавить несколько записей обоими способами; прокрутить длинный список; проверить читаемость и отступы на разных размерах окна. Перезапустить приложение и убедиться, что записи, описания и времена создания сохранились. Порядок списка и сочетание клавиш для многострочного текста ещё нужно определить.

## 3. JOY-DATA — хранение и расширяемые данные

- [x] **DATA-01:** обеспечить долговременное сохранение всех категорий и связанной информации, не только Inbox.
- [x] **DATA-02:** реализовать SQLite как рабочее локальное хранилище; единый `.xlsx` использовать для обмена и восстановления всей пользовательской системы.
- [x] **DATA-03:** хранить время создания в UTC; предлагаемый обменный вид — ISO 8601 с `Z`, например `2026-11-08T12:00:00Z`. Локализация времени не обязательна.
- [x] **DATA-04:** сохранять все поддерживаемые атрибуты, в том числе будущие приоритет и длительность, когда эти поля будут определены.
- [x] **DATA-05:** предусмотреть расширение схемы и сохранение дополнительных полей при экспорте и последующем импорте. Новое поле добавлять в модель, хранение, обмен и проверки вместе.
- [x] **DATA-06:** определить устойчивую идентификацию записей, проектов и действий, чтобы связи восстанавливались однозначно.
- [x] **DATA-07:** при ошибке сохранения сообщать о ней и сохранять предыдущие корректные данные; выбрать и проверить способ безопасной записи.
- [x] **DATA-08:** сохранять идентичность и связи папок, подпапок, проектов и действий, включая пустые подразделы, их названия, описания и пользовательский порядок.
- [x] **DATA-09:** предусмотреть метаданные изменений и удалений, необходимые для обмена без потерь, распознавания конфликтов и повторной синхронизации (`JOY-SYNC`). Конкретный механизм пока не выбран.
- [x] **DATA-10:** показывать порядковый номер задачи по времени создания UTC и устойчивому ID как второму ключу. При синхронизации независимые задачи с одинаковым предварительным номером сохраняются раздельно и получают разные номера в объединённой последовательности; номер не является идентификатором или ключом конфликта.

**Приёмка:** после перезапуска восстанавливаются все категории, атрибуты и связи. Экспорт и импорт в пустое хранилище воспроизводят поддерживаемые данные, включая дополнительные поля. Конкретные типы, единицы длительности и шкала приоритета пока не заданы.

## 4. JOY-XLSX — экспорт и импорт всей системы

### Полная книга

- [x] **XLSX-01:** экспортировать систему в Excel `.xlsx`, разделяя папки по отдельным листам.
- [x] **XLSX-02:** включать название, описание, время создания и остальные поддерживаемые атрибуты каждой записи.
- [x] **XLSX-03:** определить документированную схему книги: верхнеуровневые папки — листы, подпапки представлены внутри соответствующего листа; проекты и действия восстанавливаются с их группировкой и порядком.
- [x] **XLSX-04:** предусмотреть версию схемы и расширяемые поля. Схема и размещение служебных данных пока являются проектным решением.
- [x] **XLSX-05:** импортировать все категории из одной книги, переносимой между устройствами.
- [x] **XLSX-06:** перед применением предлагать **Add / Дополнить** и **Replace / Заменить**. По умолчанию выбрано и визуально приоритетно безопасное дополнение.
- [x] **XLSX-07:** дополнение сохраняет существующие данные и добавляет импортируемые. Правило обработки совпадающих идентификаторов и повторного импорта определить отдельно; не перезаписывать существующие записи молча.
- [x] **XLSX-08:** явно показывать область замены и ожидаемый результат до применения; замена выполняется только при явном выборе этого режима. Диалог после декодирования показывает имя файла, полную систему/Inbox и количество записей до и после; независимые widget-тесты подтверждают отсутствие изменения данных при просмотре.
- [x] **XLSX-09:** проверять файл до изменения текущих данных. Повреждённая или несовместимая книга не должна оставлять частично применённый импорт.

### Отмена импорта

- [x] **XLSX-10:** дать немедленную отмену как дополнения, так и замены, с восстановлением предыдущих данных и связей во всех затронутых категориях.
- [x] **XLSX-11:** сохранить возможность отмены как минимум сразу после импорта, до следующей операции изменения данных; явно обозначить это окно пользователю.
- [x] **XLSX-12:** проверить, что просмотр, прокрутка и переход между папками не лишают пользователя немедленной отмены.
- [x] **XLSX-13:** при Add автоматически добавлять новые папки и подпапки, если нет конфликта; сохранять существующую структуру и настройки.
- [x] **XLSX-14:** восстанавливать все пользовательские данные и переносимые настройки из одного `.xlsx`, без обязательных дополнительных файлов. Допустимое исключение — отдельно установленная необязательная модель эмбеддингов.
- [x] **XLSX-15:** сохранять пустые папки/подпапки, описания, порядок, принадлежность проектов, настройки меню разбора и сроки Trash; отмена импорта восстанавливает также эту структуру и настройки.
- [x] **XLSX-16:** определить однозначное отображение произвольных названий папок на имена Excel-листов с учётом длины, недопустимых символов и коллизий; исходные названия и идентификаторы не терять.

**Приёмка:** в системе с существующими записями импортировать другую книгу через Add: старые данные остаются. Отменить — получить исходное состояние. Повторить через Replace и отменить — восстановить исходное состояние целиком. Экспортировать и импортировать в пустое хранилище — проверить содержимое всех листов и связи проектов. Отдельно проверить некорректный файл без изменения исходных данных.

**Рабочая трактовка для последующего уточнения:** полная замена относится ко всей системе, Inbox-only замена — только к Inbox. Поведение отсутствующих листов, дубликатов и отмены после следующего изменения либо перезапуска ещё не согласовано.

Формат обмена — `.xlsx`. Упоминания «XLS/Excel» в разговоре не означают отдельного требования поддержать устаревший бинарный `.xls`. Отмена экспорта не требуется: экспорт создаёт файл и не должен менять данные приложения.

## 5. JOY-INBOX-XLSX — отдельный импорт Inbox

Нужен самостоятельный сценарий, например **“Import Inbox from Excel (.xlsx)”**, который не требует книги со всеми GTD-папками.

- [x] **INBOX-XLSX-01:** импортировать отдельный Inbox из `.xlsx`, в том числе из простого единственного столбца без заголовка.
- [x] **INBOX-XLSX-02:** в таком столбце каждая непустая ячейка каждой строки становится отдельной записью; первую строку без заголовка считать данными.
- [x] **INBOX-XLSX-03:** поддержать данные с описанием и без описания, со временем создания и без него; определить выбор или сопоставление колонок для многоколоночного варианта.
- [x] **INBOX-XLSX-04:** один раз зафиксировать UTC-время загрузки файла. Всем записям без исходного времени присвоить **один и тот же timestamp этой загрузки**, а не отдельное время обработки каждой строки.
- [x] **INBOX-XLSX-05:** сохранять корректное исходное время, если оно явно присутствует и распознано. Обработку неверного времени описать отдельно.
- [x] **INBOX-XLSX-06:** применить безопасный выбор Add/Replace и отмену импорта; не затрагивать другие категории при Inbox-only импорте.
- [x] **INBOX-XLSX-07:** пропускать пустые строки; для неоднозначных заголовков или колонок не терять первую задачу, а дать уточнить сопоставление.

**Приёмка:** книга без заголовка с тремя названиями и пустой строкой создаёт ровно три записи; первая не теряется, все три имеют строго одинаковое время загрузки. Проверить отдельный вариант с описаниями и вариант с исходными временами. Отмена возвращает прежний Inbox, остальные категории неизменны.

## 6. JOY-PROJECTS — создание и структура проекта

При обычном перемещении записи из Inbox в Projects сразу открывается форма заполнения проекта.

| Поле | Требование |
| --- | --- |
| Название | Обязательное; исходное название Inbox использовать как основу. |
| Описание | Входит в обязательное заполнение проекта согласно текущему описанию владельца. |
| План | Обязательный свободный текст, без проверки его структуры или содержания. |
| Действия / задачи | Минимум одно непустое действие; можно последовательно добавлять второе, третье и далее. |
| Критерий завершения | Обязательный; пользователь описывает, когда проект считается завершённым. |
| Время создания | Сохраняется и участвует в обмене; правило сохранения исходного времени при преобразовании уточнить. |

- [x] **PROJECTS-01:** открыть форму при переводе записи из Inbox в Projects, сохранив её название и описание для заполнения.
- [x] **PROJECTS-02:** реализовать все поля и обязательность из таблицы; для плана не вводить специальный синтаксис или семантическую валидацию.
- [x] **PROJECTS-03:** показывать минимум одно поле действия; кнопкой `+` сохранять введённое действие в форме и добавлять следующее поле.
- [x] **PROJECTS-04:** сохранять последовательность действий; не задавать искусственный продуктовый лимит на их количество.
- [x] **PROJECTS-05:** ограничить высоту подблока действий: ориентировочно три видимых поля, далее внутренняя прокрутка. Вся форма и кнопка сохранения остаются доступными на небольшом экране.
- [x] **PROJECTS-06:** сохранять проект после заполнения обязательных полей и минимум одного действия.
- [x] **PROJECTS-07:** при отмене формы не терять исходную запись; согласовать точный сценарий возврата.
- [x] **PROJECTS-08:** обеспечить однозначный экспорт и импорт нескольких проектов с несколькими действиями каждый.
- [x] **PROJECTS-09:** поддержать третье измерение организации: `Projects → подпапка/группа → конкретный проект → его действия`. Проект не должен подменять пользовательскую подпапку.

- [x] **SUGGEST-07:** показывать название и контекст назначения, если подсказка из другой папки/подпапки; определить область поиска по категориям и отдельно поведение Trash.

**Приёмка:** проверить полное совпадение, подстроку, разные формы слов, одиночное слово и отсутствие совпадений. Прокрутить много подсказок, сохранив черновик; затем явно выбрать одну — новая запись не создаётся, существующая не изменяется. Строгий набор правил по приставкам и языкам согласовать на примерах: одних регулярных выражений может быть недостаточно.

## 16. JOY-SYNC — прямая синхронизация устройств по Wi-Fi

### Обязательное поведение

- [ ] **SYNC-01:** синхронизировать компьютер и телефон напрямую в общей локальной сети: домашний Wi-Fi или сеть, раздаваемая телефоном через LTE/другую мобильную связь. Внешний сервер синхронизации и облачный аккаунт не требуются. Реализовано и проверено через настоящий HTTP на loopback; домашняя сеть и телефонная точка доступа требуют проверки на двух физических устройствах.
- [ ] **SYNC-02:** предоставить простую команду Synchronize, понятное подключение устройств и краткую инструкцию в интерфейсе; не требовать от пользователя разбираться в портах для обычного случая. Ручной адрес и код реализованы; удобство подключения на реальной паре устройств ещё не проверено. mDNS и QR не реализованы.
- [x] **SYNC-03:** переносить новые записи с обоих устройств, папки/подпапки, проекты/действия, редактирования и поддерживаемые настройки, в том числе меню разбора. Не выбирать победителя по числу файлов или записей.
- [x] **SYNC-04:** при различии версий показывать понятное сравнение: устройства, папка/запись, значения изменённых полей «здесь» и «на другом устройстве», выделенные различия и выбор сохраняемой версии.
- [x] **SYNC-05:** позволить сохранить все независимые новые записи с обеих сторон. Противоречащие изменения одной записи, переносы и удаление против редактирования не разрешать незаметной перезаписью.
- [x] **SYNC-06:** поддержать случай «изменено на одном, на другом осталось старое»: распознавать старую копию, показывать разницу по запросу и предусмотреть явный выбор версии. Автоматический перенос одностороннего изменения допустим как предложенный вариант, если история доказывает отсутствие конфликта; не считать более старую копию новым редактированием.
- [x] **SYNC-07:** перед применением показывать результат объединения и нерешённые конфликты; не объявлять синхронизацию успешной, пока её согласованный результат не сохранён на обоих устройствах.
- [x] **SYNC-08:** обеспечить повторный запуск без размножения записей, сохранение обеих исходных версий при неразрешённом конфликте и отсутствие потери данных при обрыве связи.
- [x] **SYNC-09:** учитывать удалённые записи и очистку Trash, не воскрешая их из устаревшей копии; предусмотреть конфликт удаления с редактированием.
- [x] **SYNC-10:** оставить полноценный альтернативный перенос/восстановление одним XLSX. Все необходимые для восстановления пользовательской системы данные помещаются в книгу; модель может устанавливаться отдельно.

Фраза «где больше файлов, подтянуть туда, где меньше» трактуется как пожелание дополнить неполную копию. Количество элементов не определяет свежесть: устройство с меньшим числом записей может содержать новые правки и корректные удаления. Требование сохранности и явного разрешения различий имеет приоритет.

### Предлагаемый сценарий подключения — для проектирования и проверки

1. На первом устройстве открыть Synchronize → **Make this device available**. Приложение открывает временный локальный приёмник на свободном порту и показывает имя устройства, код сопряжения и QR с параметрами соединения.
2. На втором устройстве открыть Synchronize → **Nearby devices**, выбрать устройство и подтвердить код. Локальное обнаружение, например mDNS, — кандидат; QR или ручной адрес/IP с портом — запасной путь.
3. Оба приложения подтверждают нужного партнёра; обмениваются изменениями напрямую, показывают предварительный результат и различия, пользователь решает конфликты и применяет результат.
4. Оба приложения показывают завершение; временный приёмник закрывается или остаётся доступен только в явно включённом режиме.

Порт — адрес службы, а не идентификатор устройства; одинаковое число порта на двух устройствах само по себе не соединяет их. QR/короткий код должны содержать или разрешать необходимые параметры без внешнего сервера. Транспорт, подтверждение партнёра и защита локального обмена пока не выбраны. При изоляции клиентов точки доступа/ограничениях ОС показать конкретную причину и доступную альтернативу, а не обещать соединение в любой сети.

**Предложение для модели данных:** устойчивые ID, версии/история изменений и отметки удаления помогают отличить независимое добавление, старую копию и конфликт. Передавать можно изменения или файлы, в том числе книгу; ни один вариант не отменяет поэлементного объединения. Служебные сведения для восстановления и корректного повторного обмена следует учитывать в XLSX-схеме.

**Приёмка:** на двух устройствах в домашней сети, затем в сети телефонной точки доступа выполнить сопряжение, добавить разные записи на каждом и объединить — все остаются. Проверить одностороннее изменение, разные правки одной записи, перенос между подпапками, изменение настроек и удаление против редактирования. Показать diff и выбрать сторону. Прервать связь, повторить обмен — нет потери, дубликатов и ложного сообщения об успехе. Проверить повторный обмен после восстановления из XLSX. Обмен не должен зависеть от внешнего сервера.

## 20. JOY-DISTRIBUTION — лёгкий запуск Windows

Уточнение владельца от 2026-11-09: обычный пользователь не должен устанавливать Flutter, Visual Studio и собирать программу. Для Windows нужны готовые файлы, запускаемые как обычное приложение.

- [x] **DIST-WIN-01:** собрать готовую Windows x64 release-версию; Flutter, Python, Java, Visual Studio и отдельная SQLite не требуются на компьютере пользователя.
- [x] **DIST-WIN-02:** предоставить portable ZIP с полным набором DLL/данных и установщик с ярлыками.
- [x] **DIST-WIN-03:** включить runtime-библиотеки в пакет; устанавливать приложение для текущего пользователя без требования прав администратора.
- [x] **DIST-WIN-04:** хранить базу отдельно от программы и проверить, что удаление приложения не меняет файлы пользовательской базы.
- [x] **DIST-WIN-05:** автоматизировать сборку и проверку реального запуска на Windows; выпустить проверенные файлы с контрольными суммами и простой пользовательской инструкцией.

Приёмка сборки, runtime и установки: [WINDOWS_VALIDATION.md](WINDOWS_VALIDATION.md), успешный Windows-прогон и инспекция скачанных пакетов. Публикация файлов и конкретные хеши подтверждаются метаданными релиза. Пользовательская инструкция: [WINDOWS.md](WINDOWS.md). Подпись сертификатом издателя не заявляется; обычные ограничения SmartScreen указаны явно. Поставка macOS не считается завершённой этим Windows-пакетом.
